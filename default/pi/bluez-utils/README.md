# BlueZ 5.87 system-bus backport

The stable ARM repository supplies `bluez-utils 5.87-2`. Its `bluetoothctl` passes a null connection to libdbus when connecting to the system bus fails, aborting before it can query a controller. This is visible in restricted agent sandboxes and does not establish a Pi radio or firmware fault. Upstream fixed it in [a57c6d52](https://github.com/bluez/bluez/commit/a57c6d52e7cc87e30768d09aadff4c7b3a736938), tracked by [BlueZ #2446](https://github.com/bluez/bluez/issues/2446).

This recipe builds the 5.87 client with that patch and packages it as `bluez-utils 5.87-2.1`. Only the patch context changes from upstream. The remaining utilities, manual pages, completions and user unit come unchanged from the exact ALARM package. The archive SHA-256 was checked against the package signed by the Arch Linux ARM build key `68B3537F39A313B3E574D06777193F152BDBE6A6`. All sources and local build inputs have checksums; no integrity checks are disabled. Rebuilding only the client avoids adding unrelated daemon/library changes or the full BlueZ build dependencies to Pi updates.

`install/helpers/rpi4-bluez.sh` builds in the existing disk-backed makepkg environment and memory-aware job limits and removes its temporary workspace. The shared installer runtime step runs it for fresh installs, image builds and updates before verifying the package contract. Reconciliation preserves an installed `5.87-2.1` when the repository still supplies `5.87-2`; the exact-version exception does not apply to newer repository versions. The backport does not change repositories, signature policy, `IgnorePkg`, Bluetooth service configuration or pairings.

`check-system-bus.py` runs the built client against a nonexistent socket and requires normal exit status 1 with a useful error. Hardware validation additionally runs `bluetoothctl list` against the live system bus and, from a restricted agent command, verifies that denial also exits 1 without aborting. An inaccessible bus still needs a normal terminal or an individually authorized host command to perform Bluetooth operations; the patch does not grant sandbox access.

When the selected stable ARM package includes the upstream fix, remove this recipe, helper and exact-version exception together. Do not move to a rolling repository or partially upgrade system libraries to obtain it. A local rollback can reinstall the original signed `bluez-utils 5.87-2` archive with pacman; it restores the known crash behavior. No reboot or Bluetooth daemon restart is required for either client replacement.
