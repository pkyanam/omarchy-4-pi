# Omarchy 4 Pi — Release Candidate 1

RC1 is a community testing release for **Raspberry Pi 4 Model B, ARM64**. It packages the full Quattro desktop with a smaller optional-app footprint. It is not yet a stable release or an official Omarchy/Raspberry Pi image.

## What's new

- **Your hostname comes first.** Imager's chosen short hostname is set and read back before SSH setup. mDNS waits for owner provisioning, avoiding early advertising of the factory name during the normal first-boot sequence.
- **First-boot failures stay failures.** Unattended provisioning runs in its own shell so Bash does not suppress errors deep inside account or hostname setup. A failed attempt retains the interactive recovery path.
- **A display rescue button.** `omarchy-pi-display` shows HDMI modes and EDID state. Its NEC EA243WM profile previews 1920×1200 at 60 Hz and 1× scale, then saves only after confirmation. Reset retains a backup.
- **Useful power checks on the generic kernel.** Native Raspberry Pi voltage and thermal sensors are used when the legacy `vcgencmd` interface is unavailable, carried forward from alpha.8.
- **Clearer public docs.** One catalog-based flashing path, explicit hostname and SSH instructions, safe diagnostic reporting, honest hardware coverage, and a friendlier issue form.
- **Release gates.** Tagged image builds run the focused Pi regressions before assembly, verify the real ARM64 Hyprland configuration, and audit hostname ordering and display-helper installation in the mounted filesystem.
- **Coherent factory packages.** The first build attempt caught upstream Aquamarine advertising library version 14 while Hyprland still required 13. RC1 uses the full September 3, 2026 snapshot from `pkgmirror.sametimetomorrow.net`, a community archive, with Arch Linux ARM package signature enforcement unchanged. The image restores normal live mirrors before shipping; no library symlinks, skipped dependency checks, or permanent package holds are used.

## Flashing

Use Raspberry Pi Imager **2.0.11+** through the RC1 catalog, not “Use custom,” to expose account, hostname, Wi-Fi, and SSH customization. See the [README](../../README.md#flash-boot-make-it-yours) for the macOS launch command. The catalog is ready only when this release contains its image and `os-list.json` assets.

Set `omarchy-pi` (or another short name) in Imager, not `omarchy-pi.local`. With SSH enabled, connect as `YOUR_USERNAME@omarchy-pi.local`. First boot expands storage and provisions your owner account before the desktop starts. No reusable factory login is shipped. Back up the target card: flashing erases it.

## Evidence and remaining acceptance

On September 4, 2026, the tester reported RC1 working on their Pi 4 and approved publishing it as the project's first release candidate. This is an initial on-device success report, not a completed per-feature acceptance report. Hostname discovery after reboot, saved display settings, actual audio playback, Bluetooth pairing, sustained thermals, and updates still need explicit results.

An earlier alpha.7 image booted on a real Pi 4 Model B Rev 1.5 with V3D, SDDM, Hyprland, Quickshell, networking, and successful owner/root-expansion markers. PipeWire had a default sink and Bluetooth a powered controller; those checks do not prove playback or pairing. Native sensors reported no active undervoltage and 43.8°C at one point, not a sustained load test.

The NEC EA243WM's EDID read was empty through the tested micro-HDMI-adapter/HDMI cable chain. The tester reported that the explicit native modeline appeared to work. RC1 packages that timing as an opt-in recovery profile; the new helper and new image still require an on-device test. No global resolution override is imposed on other displays.

Before stable release, a fresh RC1 card must pass:

1. Imager account, keyboard, timezone, Wi-Fi, and opt-in SSH setup without a keyboard attached.
2. The requested hostname in `hostnamectl --static` and the receipt, with `.local` discovery after initial boot and after reboot.
3. Desktop input, native monitor mode, saved display profile after reboot, and a complete `omarchy-pi-check` report.
4. Actual audio playback and Bluetooth pairing, network reconnection, a clean reboot, and sustained power/thermal observation.
5. The Pi-aware update path without changing ARM repositories or losing personal settings.

Results are tracked in the [hardware checklist](https://github.com/pkyanam/omarchy-4-pi/issues/1). Automated tests and a mounted-image audit cannot replace that pass.

## Known limits

- Missing EDID can still affect HDMI audio; a custom modeline restores video timing only.
- The default ext4 image is unencrypted and has no Snapper rollback/factory reset. Keep backups.
- Optional unavailable/x86-only applications are omitted; Pi 5, Pi 400, DSI panels, HATs, and all USB enclosures are not validated.
- Source updates do not replay first-boot service setup. Use a spare card to test the actual RC1 image without losing your older install.
- The signed base filesystem and some build inputs still roll forward, so builds are not byte-for-byte reproducible. The attached manifest records the factory package snapshot, resolved package versions, and source revisions.

Factory package databases come only from the dated snapshot. Official mirrors are used as package-only cache servers for identical filenames, with snapshot hashes and required package signatures still checked. Single-file download concurrency and longer retry delays reduce load on the community archive. These build-only settings are replaced by the normal live ARM configuration before shipping.

The release includes `.img.xz`, `.img.xz.sha256`, `.manifest.json`, `.audit.txt`, and Imager catalogs. Imager uses the catalog's compressed/extracted sizes and SHA-256 hashes. For a manual download, run `shasum -a 256 -c IMAGE.img.xz.sha256` in its directory. The manifest and audit identify what was built and checked; they are not a hardware-certification claim.
