# Omarchy 4 Pi 4.5.0

Omarchy 4.5 for Raspberry Pi 4 Model B with 4GB or 8GB RAM. This release integrates upstream 4.5.0 (`ac2690cd7be4f47e4a255f5e2e78d904d436b068`) with the Pi boot chain, owner provisioning, update safeguards and resource defaults. The maintainer reported the preceding 4.5 candidate booting and running; separate 4GB/8GB performance and peripheral qualification remain open. Pi 5 is deferred.

## Install

Use spare media with Raspberry Pi Imager 2.0.11 or newer. Download the release image and verify its SHA-256 checksum, or use the release's `os-list.json` catalog when available. Select the Pi 4 and Omarchy 4 Pi entries, set your account, short hostname, network and optional SSH access, then write and verify. There is no reusable factory login.

If GitHub assets are split, download every numbered part and both checksum files. Follow the included `REASSEMBLE.txt`, then use `image/open-in-rpi-imager-macos.sh IMAGE.img.xz` on macOS or generate a local catalog with `image/generate-local-imager-manifest.sh IMAGE.img.xz` on Linux. This retains Imager customization. [Complete instructions](../../README.md#flash-with-raspberry-pi-imager).

Existing 4.0/rolling images need a fresh-media transition. Do not force an in-place package downgrade or bypass the updater's repository checks. Keep the old card as rollback. [Migration guide](../pi-upgrade.md).

## Changes

- The complete 4.5 desktop, including floating workspaces and dock, updated shell and applications, and expanded translations.
- A coherent signed stable ARM64 package set with the adapted Pi core/settings packages and firmware/U-Boot boot chain preserved.
- Stock clocks, conservative desktop effects, bounded package/build workloads, half-RAM compressed swap and bounded logs.
- Paper Mono, bundled with its SIL Open Font License.
- Reliable first-user provisioning, root expansion, hostname/SSH choices, packaged offline Node/npm and retryable fresh installation checkpoints.
- Pi-aware updates from this fork's clean `main`, with legacy rolling, dirty source and wrong-repository transitions refused.
- README quick start, Codex setup and a Pi-specific guide linked from the built-in Omarchy skill.

## Validation and limits

The published production image passed 192 mounted-root checks, the actual native ARM64 Hyprland configuration parser, ext4/FAT checks, dynamic-library checks for Hyprland/Quickshell/titlebars, systemd unit verification, Chromium startup/version execution, offline Node/npm execution as a fresh unprivileged user, the installed production update guard, and actual ARM64 Codex first-use installation/launcher execution. Codex authentication and a model session were not part of that probe. Focused source fixtures cover packages, provisioning, updates, resource policy and image integrity. Release assets carry the exact source, recipe and package manifest, checksum and audit report.

These checks do not establish GPU/plugin execution in a real desktop session, hardware video decode, every peripheral, sustained thermals or Raspberry Pi OS performance parity. The maintainer's boot/run report is separate from detailed board qualification. The image uses plain ext4 without automatic Snapper rollback; keep backups. [Evidence and remaining checks](../../plans/omarchy-4.5-pi4.md).

## First steps

Run `omarchy-pi-check` and `omarchy pi report --json`. Choose Codex with `omarchy default agent codex`, sign in, and ask it to use the Omarchy skill and Raspberry Pi guide for configuration or troubleshooting. Network access and your own provider authentication are required for agent setup. Subsequent published-image updates use `omarchy update`.
