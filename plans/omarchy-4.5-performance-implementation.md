# Omarchy 4.5 Pi 4 performance implementation

Scope: Pi 4 Model B 4GB and 8GB, fresh 4.5 candidates. Implementation against the shared in-progress merge of exact upstream `ac2690cd7be4f47e4a255f5e2e78d904d436b068`, with original fork baseline `393f48c3`. Pi 5 remains deferred. No Git staging/commit/reset/merge/push, containers, builds, host installation/update, publication, or device changes were performed by this implementation agent.

## Implemented behavior

- `bin/omarchy-pi-run` explicitly requests `--slice=app.slice`, preserving literal argv, CPU quota/weights, memory high/max and scope failure propagation. It reuses the shared build budget rather than overwriting a tighter caller budget. This puts the requested scope beneath the subtree monitored by the existing app-only oomd policy; live cgroup placement and enforcement still require Linux verification. It does not reserve a CPU core, prevent aggregate overcommit from several workloads, or protect the desktop from the kernel OOM killer.
- `bin/omarchy-pi-status` handles GLX failure without losing native power, temperature, memory or disk reports. It only attempts GLX with `DISPLAY`, captures the diagnostic before parsing to avoid early-reader SIGPIPE, preserves colons inside a renderer name and labels GLX/XWayland separately from the compositor renderer. Missing data stays unknown. No native EGL tool or dependency was added; actual Wayland rendering remains unverified.
- `default/pi/build-budget.sh` supplies at most two jobs below 5GiB total RAM, at most three above that threshold, at most `nproc - 1` when more than one CPU is available, and at most one job below 2GiB available RAM. It bounds existing loose/unbounded Make/Cargo/CMake hints and retains tighter positive job limits. Zstd and xz use bounded threads and level 3; xz has a 25% compression memory ceiling. Existing tighter compression thread hints and tighter xz memory limits from the environment or makepkg arrays are retained. It never changes architecture flags. These are compiler hints; an explicit recipe-level `ninja -j...`, linker peak or a separate service can exceed them.
- `install/hardware/raspberry-pi.sh` delegates boot configuration to `default/pi/firmware-config.py`. It stops before module/package changes if firmware review is required, including when sourced inside a Bash conditional. The parser handles model applicability, `[all]`, `[none]`, ordering, and an existing single applicable full KMS overlay. It leaves that overlay and its parameters in place, adds one only when needed for Pi 4, and puts scalar/audio settings in a deterministic final Pi 4 block. `dtoverlay=` closes overlay-parameter context before the base audio setting. An earlier `audio=on` followed by `audio=off` no longer defeats the final audio setting. An inactive Pi 5 overlay does not satisfy Pi 4 KMS.
- Firmware changes preserve unrelated text, clocks, voltage, thermal limits, CMA and `gpu_mem`. Includes, ambiguous/missing boot paths, symlinks, uncertain conditional KMS/audio settings, duplicate applicable KMS overlays, FKMS, explicit KMS `noaudio`, malformed/edited managed blocks, or settings added after the managed block cause refusal. No guess or partial firmware write follows. Successful changes retain `config.txt.omarchy-before-kms`; later changed input gets an additional unique recovery copy. The update uses a same-directory temporary file, fsync and atomic rename after rechecking the original. Repeating an unchanged setup does not rewrite config or backups.
- `default/hypr/raspberry-pi.lua` retains `AQ_NO_MODIFIERS=1` and marks conservative Pi graphics policy. The one-condition guard in `workspace-modes.lua` prevents entering floating mode from silently enabling disabled shadows. It preserves existing explicitly enabled shadows, floating rules, opacity, titlebars, minimize/restore and dock code. Hardware A/B evidence is required before changing the modifier workaround.
- `install/user/hardware/raspberry-pi.sh`, called before `theme.sh` in `install/user/all.sh`, seeds `default/pi/user-defaults.py` only for `iso-chroot`/`provision-owner` contexts. A saved theme/background, completed finalization, or its own completion marker prevents re-seeding. Fresh accounts get upstream's coherent `no-animations.lua` toggle, `background-intros-off`, a remembered static Tokyo Night `0-liftoff.webp`, and an opaque bar when shell.json has not already been seeded. The shipped 4.5 shell.json is already opaque; custom bar/dock JSON is never rewritten. Removed toggles and existing theme/font choices survive later finalization.
- Official desktop Paper Mono TTFs and the unchanged SIL OFL are self-hosted in `default/pi/fonts/paper-mono/`. Only fresh users without a fontconfig choice receive private font copies and `default/pi/fonts.conf`; byte-identical shipped terminal defaults can then use Paper Mono. Custom terminal files remain untouched. Nerd Font and Omarchy glyph fallbacks are preserved. Font source, weight metadata and hashes are recorded in the font README. These are desktop TTFs, not WOFF2 files substituted into fontconfig.

The imported upstream bounded image-decoding implementation and broad shell QML were left intact. No polling timer, telemetry daemon, clock/CMA/gpu_mem tuning, local inference service, or compositor-wide feature removal was added. Native health and opt-in tuning guards remain unchanged.

## Build integration interface

Use this in the current shell before any staging, `mktemp` build directory, bootstrap recipe, or core makepkg invocation:

```bash
source "$OMARCHY_PATH/default/pi/build-environment.sh"
omarchy_pi_prepare_build installer
# Compose with existing cleanup; do not replace its trap blindly.
trap 'omarchy_pi_cleanup_build' EXIT
makepkg --config "$OMARCHY_PI_MAKEPKG_CONF" ...
# Retain/copy packages and receipts outside the owned child before cleanup.
```

`omarchy_pi_prepare_build [label]` requires an alphanumeric/underscore/hyphen label and exports `OMARCHY_PI_BUILD_WORK`, `OMARCHY_PI_BUILD_CACHE`, `OMARCHY_PI_MAKEPKG_CONF`, `TMPDIR`, `OMARCHY_PI_BUILD_JOBS`, `MAKEFLAGS`, `CARGO_BUILD_JOBS`, `CMAKE_BUILD_PARALLEL_LEVEL`, `ZSTD_NBTHREADS`, `ZSTD_CLEVEL`, `XZ_OPT`, `BUILDDIR`, `SRCDEST`, and `SRCPKGDEST`. Compression arrays cannot be exported through the environment, so **every makepkg call must use the generated `--config` file**. That config sources the base makepkg configuration, reapplies the Pi budget, and sets private `BUILDDIR`, `SRCDEST`, `SRCPKGDEST` and `PKGDEST`. An explicit caller `PKGDEST` is checked and preserved, and is never deleted by cleanup. Pass the exported environment through sudo/runuser when relevant; the invoking build user must own/read the private workspace. Do not create it as root and expect a different user to access a mode-700 tree.

Workspace parent precedence is `OMARCHY_PI_BUILD_PARENT`, then explicit `TMPDIR`, then `${XDG_CACHE_HOME:-$HOME/.cache}/omarchy/pi-build`. A unique mode-700 child contains private temporary, compiler and package/source-cache directories. No HOME override, graphical user manager, chroot requirement, automatic trap, service or persistent system change is used. Inherited `BUILDDIR`, `SRCDEST` and `SRCPKGDEST` are replaced with checked private locations as well: makepkg otherwise restores those environment variables after reading its config.

Storage checks use `findmnt`, `df -Pk`, and `df -Pi` before staging. Supported disk filesystems are ext2/3/4, btrfs, xfs, f2fs, zfs and bcachefs. tmpfs/ramfs and overlay are rejected because backing storage cannot be proved there; bind an actual disk filesystem into containers/chroots and select it explicitly. Default preflight minimums are 6GiB free and 50,000 free inodes; callers can raise task estimates with positive integer `OMARCHY_PI_BUILD_MIN_KIB` and `OMARCHY_PI_BUILD_MIN_INODES`. Free-byte checks always apply. A zero-total inode table is accepted only for btrfs/zfs/bcachefs, which allocate dynamically; fixed-capacity ext4 exhaustion and an unknown zero-total ext4 report still fail. Parent verified `/mnt/work` in volume `omarchy45-validation-work` as btrfs `/dev/vdb1`, about 43GiB free, with the dynamic zero-total inode report; this is parent evidence, not a container check performed here.

`OMARCHY_PI_MAKEPKG_BASE_CONF` defaults to `/etc/makepkg.conf` and can name another readable base for a fixture/build host. Use absolute paths. Same-process repeated preparation rechecks storage and reuses the workspace. Cleanup requires the exact owner marker and owning Bash process; an inherited path, changed/missing marker, symlink or substituted directory is not deletion authority. A subshell does not delete its parent's workspace. The selected parent, unrelated sentinels and explicit persistent package output survive cleanup. TMPDIR and the three makepkg build/source paths are restored when they still name this invocation's private directories. Build limits are hints, not a substitute for the parent's bounded factory resources.

## Packaging and administrator overrides

The package agent owns recipe changes and removes the conflicting vendor `90-omarchy.conf` zram policy and upstream `vm.*` sysctl policy for the Pi package. This is required: merely having the Pi drop-in present would not defeat a later vendor zstd/whole-RAM configuration. The existing `omarchy-apply-pi-performance` remains responsible for half-RAM zram with the running kernel's default compressor, app-only oomd, writeback/journal limits and stock CPU-policy/opt-in guard units. No unsupported zstd compressor is requested for zram.

Administrator drop-ins retain normal lexical priority: for example `99-local.conf` after the Pi zram `50-omarchy-pi.conf`, and `99-z-local.conf` after Pi sysctl `99-omarchy-pi-writeback.conf`. The latter's `99-` prefix alone does not make an arbitrary `99-local.conf` sort later. Inspect merged configuration and live state after reboot; this implementation does not overwrite user graphics/theme/font/clock choices during a core update. No new root apply policy file was needed within this ownership group.

## Validation and remaining gates

`/opt/homebrew/bin/bash test/shell.d/rpi45-performance-test.sh` writes its complete output to `/tmp/rpi45-performance-mac.log`. Eight behavioral groups passed: shared budgets; private storage/config/cleanup and persistent outputs; tmpfs/overlay/space/inode refusal including the btrfs/ext4 distinction; app.slice/literal argv/scope failure; GLX failure/Wayland-only reports; section-aware firmware ordering/refusals/backups/idempotence; sourcing-context firmware failure propagation; and new-user defaults/owner preference preservation. The ninth Lua group is explicitly skipped because Mac host `lua` is unavailable; it exercises the real floating module's Pi/non-Pi shadow behavior while preserving opacity/titlebar setup, and must run in the parent's Linux environment. No Lua binary was installed here.

Warning-level ShellCheck for the owned shell implementation and new test passed; log `/tmp/rpi45-performance-shellcheck.log`. Bash 5 syntax and in-memory Python compilation passed. Font verification inspected the official SFNT name tables, desktop TrueType signatures, OS/2 weights and SHA-256 hashes before retaining the assets. The installed Mac fontconfig tools also scanned all four TTFs and resolved `monospace` to `Paper Mono Regular` using a private config that loaded the real packaged `50-omarchy.conf` followed by the Pi preference, with all cache writes confined to the fixture; this does not verify Qt rendering on Linux. The test source names the breakages it catches and sources `base-test.sh`; no existing shared test file was edited. Fixtures simulate only environment/dependency interfaces and exercise the actual budget, parser, setup and command implementations.

The parent owns consolidated Linux fixture tests, real makepkg configuration handling, native aarch64 package/image builds, effective zram/sysctl/oomd and controller checks, manifest/rootfs audits and the aggregate suite. These source/fixture results establish no boot, media acceleration or speed result. Follow the repository visual-verification guide on physical Pi 4 4GB and 8GB: static wallpaper/startup without intro covers, shell/bar/fonts/icons, reduced motion, floating/titlebars/dock/minimize/restore, display, audio, lock/wake, capture and representative load. Paper Mono layout/fallback, actual V3D renderer, app.slice cgroups, pressure and memory limits, firmware boot/audio behavior, and resource budgets remain unverified on hardware. Keep stock clocks and `AQ_NO_MODIFIERS=1` pending measured hardware A/B testing; do not promote or publish a candidate based on fixtures alone.
