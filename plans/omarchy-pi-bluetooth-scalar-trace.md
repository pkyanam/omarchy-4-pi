## Safety and lifecycle

Default invocation only prints the offline plan. `--validate-probes` requires root and a fresh output directory; it installs the exact UUID-group events disabled in one isolated instance, saves and checks every installed format (exact scalar names, widths and signedness), then removes everything without touching binding. `formats.json` contains a hash of format text normalized only to remove volatile event name/ID headers. After reviewing these formats, the parent supplies that hash with `--execute --expected-formats`. Execution reinstalls and compares formats before enabling events or rebinding. Format mismatch, missing symbols or install errors stop before binding.

Both live modes share `/run/lock/omarchy-bt-transport.lock` with the old helper. Preflight rejects a wrong kernel/architecture/CPU count, nonzero taint, unexpected binding, busy global tracer/events, existing instances or dynamic probes. Global `tracing_on=1` with `nop` and no events is idle and is preserved. Snapshots include global tracer, tracing flag, clock/options, filters, event state, probe definitions, instance inventory, taint/binding, global buffer size and readable dynamic-debug policy. A second comparison precedes installation; execution checks again immediately before unbinding, excluding only owned UUID resources. No shared policy is overwritten to force restoration. The lock cannot exclude unrelated root tracers; parent coordination remains required because tracefs offers no transaction spanning multiple control writes.

Owned instance controls: nop tracer, mono clock, 128 KiB per CPU, overwrite disabled, stack/address/offset/branch/fork options disabled where supported. Global record-cmd and record-tgid have no instance controls in this exact kernel; they are never written. Only the selected event enable files are enabled inside the instance. The nominal 12-second window includes at most two seconds for unbind and eight seconds for the one normal bind. One unbind only; a failed or timed-out normal bind is never retried. Cleanup can make one four-second recovery bind only when this run attempted unbind but never attempted normal bind, the device is detached, and its worker has settled.

Probe commands are appended individually to `kprobe_events`, never truncating shared definitions. UUID event ownership is journaled before installation so a write that commits then raises is cleaned up. Partial installs remove only journaled names whose definitions still match the installed or requested command. Changed definitions are left untouched and reported. Removal uses individual `-:GROUP/EVENT` commands; no wildcard/global removal occurs. A vanished event needs no deletion. The instance is disabled, event enables disabled, trace/stats/profile copied, and removed with `rmdir`; no recursive filesystem deletion is used. Probe cleanup remains independent of binding recovery and trace-save failures.

Sysfs operations use only a direct owned Python child with bounded waits. Cleanup kills/waits only that child and never starts a competing bind while it remains unresolved; `result.json` records its PID if still present. Ordinary termination signals are briefly masked across instance creation/ownership marking and sysfs worker launch/ownership assignment to close side-effect bookkeeping gaps. `worker.json` records the latest worker PID and operation. Normal termination signals enter cleanup, and subsequent normal termination signals are ignored during cleanup. A kill error does not skip probe removal. SIGKILL, process death, kernel hang, uninterruptible callbacks and blocking tracefs/sysfs calls can defeat cleanup/deadlines; this is a coordinated diagnostic, not a real-time watchdog. Inspect `owned.json`, `actions.json`, `result.json` and remaining workers before any manual recovery. Never rebind repeatedly or clear unrelated probes.

Trace output is capped at 2 MiB with truncation recorded; each CPU's stats and the kprobe profile are saved before removal. The parent must reject absence-based conclusions if truncation, overruns, dropped events or probe misses occur. Generic tty symbols can serve other serdev devices; no pointer/port discriminator is captured. Use the bounded call ordering, PID/CPU context and known ownership, and do not blindly pair interleaved entries/returns. Reported baud is the setter's local `ktermios.c_ospeed`, not physical UART speed. Acceptance is a tty return, not TX FIFO progress. Flow/power are software requests/results, not measured CTS/RTS or reset voltages. RX callback length is not valid HCI or error-counter evidence.

## First registration refusal: command I/O correction — 2026-11-08

**Finding:** the original helper’s `Path.open("a")` is incompatible with this control file. The exception does not establish a compiler, blacklist, instruction, register, grammar or probe-handler failure. The parent’s first UUID `write` command was journaled, but opening the stream attempts `lseek(fd, 0, SEEK_END)` before `stream.write()` can run. That seek returns `EINVAL` in the exact kernel. This is a concrete helper I/O defect with a source-rooted correction, not grounds to alter probe fetches or kernel settings. The saved attempt has no syscall trace, so identification of its failing syscall is inferred from this deterministic source path rather than directly observed by strace.

Evidence chain (all kernel paths relative to ignored candidate `source/`):

- `kernel/trace/trace_kprobe.c:1353–1384`: `probes_open()` only deletes shared events when `O_TRUNC` is present; it calls `seq_open()`. `kprobe_events_ops.llseek` is `seq_lseek`. `probes_write()` calls `trace_parse_run_command()`.
- `fs/seq_file.c:309–341`: `seq_lseek()` initializes its result to `-EINVAL` and handles only `SEEK_CUR` and `SEEK_SET`. `SEEK_END` reaches the unchanged error return.
- [CPython v3.14.0 FileIO source](https://github.com/python/cpython/blob/v3.14.0/Modules/_io/fileio.c): append initialization calls `portable_lseek(self, NULL, 2, true)` and fails initialization on error. The seek routine suppresses `ESPIPE` only, so it propagates `EINVAL`. The downloaded versioned source is saved as `source/cpython-v3.14.0-fileio.c`, with its URL and SHA in `io-correction-source-manifest.json`. The saved parent logs do not record the installed Python version; no live Python-version query was made here.
- `kernel/trace/trace.c:9635–9691`: the command writer parses each newline-delimited command; it does not need an EOF position to add events. Opening a raw existing descriptor with `O_WRONLY | O_CLOEXEC`, omitting `O_TRUNC` and `O_CREAT`, then writing the full line once is the correct non-truncating command contract. This applies equally to owned deletion commands.
- `kernel/trace/trace_probe.c:1460–1479` and `arch/arm64/kernel/ptrace.c:53–111` support `%x2`; scalar `u64` is defined by the exact type table. The public `p:GROUP/EVENT SYMBOL FIELD=FETCH:TYPE` grammar remains supported. UUID group and `requested` field do not require renaming. No alternative registers, types, offsets or event mechanisms were tried.
- `trace_kprobe.c:1077–1086` normally logs a registration failure, and `trace_probe.c:184–230` sends errors to the global trace error log. An exception before the write never reaches these handlers, explaining the empty saved log. `trace_probe_log_clear()` clears parsing context, not the global error-log entries. Empty log alone would not prove a particular registration failure or rule out allocation failure/concurrent clearing.
