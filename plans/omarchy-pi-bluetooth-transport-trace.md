The helper discovers exact available names and module ownership at execution. Required functions are `bcm_gpio_set_power`, `bcm_open`, `bcm_serdev_probe`, and `bcm_recv`, each uniquely belonging to `hci_uart`. Optional functions cover HCI baud/flow requests, enqueue/write work/receive, tty adapter write/receive/wakeup/baud/flow/tiocm, and `uart_set_termios`. Missing or ambiguous optional symbols are omitted; missing or ambiguous required symbols abort. It never substitutes a suffixed symbol, guesses an address or installs a dependent probe. The exact requested filter is compared to the kernel's installed filter before enabling function tracing.

There are **no scalar kprobes or kretprobes**. The saved capability evidence does not validate installed argument-fetch support or exact arm64 tracing ABI. General current [ftrace documentation](https://docs.kernel.org/trace/ftrace.html) supports instance/filter/capture design; [kprobe documentation](https://docs.kernel.org/trace/kprobetrace.html) describes best-effort argument/return fetches, but is not validation of this installed kernel. Neither is sufficient to authorize guessed `$argN`, register fetches or structure offsets. Extending this candidate requires a separate source/installed-capability review, with exact declarations, widths/sign, event formats and arm64 implementation pinned before probes are enabled.

The helper records calls only. `ttyport_write_buf` entry establishes entering the adapter, **not acceptance**; `hci_uart_write_work` establishes worker execution, **not TX progress**; `bcm_recv` establishes entering the Broadcom receive callback, **not valid HCI data**. Baud/power/flow entries establish calls without their arguments, completion, return status, effective baud or pin state. Generic tty adapter and `uart_set_termios` entries may involve other serial devices; no port identifier is collected. `hci_uart_set_baudrate` can belong to the line-discipline path and need not appear during serdev host baud setup. Its absence alone proves nothing.

Global `serial8250_rx_chars`, `serial8250_tx_chars`, `serial8250_start_tx`, and `serial8250_modem_status` availability is recorded, but these functions are excluded from the filter. No validated port filter is available, and global IRQ/serial activity can produce a large, ambiguous trace. No per-byte serial functions, registers, devmem, packet bytes, buffer dereferences, physical signal values or firmware contents are read. Serial acceptance/results, TX FIFO progress, RX/error counts, effective CTS state, electrical transmission and controller readiness remain unknown.

## Parent-only execution contract

Review the helper before transporting it. Default invocation requires no root, performs no live discovery or writes, and prints JSON:

```bash
python3 tools/pi-experiments/bluetooth-transport-trace.py
```

After the parent freshly verifies tty ownership/no attach or getty, board health, storage and exclusive access, the privileged invocation on the Pi is:

```bash
python3 bluetooth-transport-trace.py --execute --output /parent/chosen/existing-parent/bt-call-trace-unique
```

The output directory must not exist; its parent must already exist. Privilege acquisition is intentionally absent: the parent owns credential transport and follows terminal `sudo` versus non-terminal `pkexec` policy separately. This lane has not executed that command. The helper starts no btmon, scans, pairing or HCI debug; any coordinated companion capture belongs to the parent and must not rebind independently.

Preflight requires the exact kernel string, `aarch64`, four CPUs, zero taint, the exact bound `serial0-0` driver, mounted tracefs at `/sys/kernel/tracing`, global `nop`, global events disabled, no instances, and no existing dynamic/kprobe definitions. It records global tracing policy, filters, clock/options, probe definitions, binding, taint and instance inventory in `before.json`, with a second shared-state comparison before setup. A nonblocking exclusive `/run/lock/omarchy-bt-transport.lock` serializes this helper only; it cannot exclude unrelated tracing tools or another root process. Parent coordination is required throughout.

Execution creates one UUID-named owned instance, with 128 KiB per CPU (512 KiB nominal total), overwrite disabled, no stack capture, and instance monotonic clock. It installs only exact selected names and records actual filter/options/clock. One unbind is allowed, followed by one normal bind; no rebind retries or module unloads occur. The nominal trace window is 12 seconds including sysfs operations. Unbind wait is at most two seconds; normal bind wait is at most eight seconds within the remaining window. Trace collection is a stopped, non-consuming `trace` read, not a blocking `trace_pipe` collector. The trace file is capped at 2 MiB with truncation recorded; per-CPU stats expose overruns/drops. Non-overwrite buffers retain the beginning and can lose later events. Absence cannot be interpreted if events were lost or symbols were unavailable.

## Restoration and exact operational limits

`finally` disables only owned tracing, kills/waits only its sysfs child, restores the original binding if detached by this run, saves its trace/stats, switches its own instance to `nop`, and removes only that instance with `rmdir`. There are no created probes/events, and the helper never writes global probe controls. If already restored, it does not bind again; if a foreign driver appears, it leaves it untouched and reports failure. Cleanup has one four-second recovery bind budget when detached, followed by at most a one-second kill/wait. This is recovery binding without a second unbind. Each cleanup step is independent so a trace-save/stop error does not skip binding recovery. It records `after.json` and treats any shared-state difference as failure without overwriting another actor's changes.

All child waits and capture storage are bounded, but Python scheduling and kernel filesystem calls are not real-time deadlines. A sysfs worker can remain uninterruptible despite SIGKILL. In that case the helper reports the unresolved worker and avoids a competing bind; parent intervention is required. SIGKILL, power loss, kernel hang, or failure to write `tracing_on` can prevent restoration or overrun the nominal window. This helper cannot promise unconditional restoration across those failures. Normal SIGINT/SIGTERM/SIGHUP raise through `finally`; subsequent such signals are ignored during cleanup. It is a parent-reviewed diagnostic, not an unattended recovery service.

On failure, inspect `result.json`, `actions.json`, `owned.json`, before/after state and any remaining worker before further operations. Do not kill unrelated PIDs, remove other instances, clear global probes, or repeatedly rebind. A retained owned instance is identified in `owned.json`; stop/remove it only after establishing why cleanup failed. A restored driver and zero taint do not establish working Bluetooth.
