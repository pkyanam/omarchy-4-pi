## Source and baseline semantics

Official [v1.5.7 release](https://github.com/meta/zstd/releases/tag/v1.5.7), [release archive](https://github.com/meta/zstd/releases/download/v1.5.7/zstd-1.5.7.tar.gz), and [published checksum](https://github.com/meta/zstd/releases/download/v1.5.7/zstd-1.5.7.tar.gz.sha256). The direct asset hostname stalled; identical official release assets were fetched through GitHub's release API (`230758919` archive, `230758922` checksum). SHA-256 verified: `eb33e51f49a15e023950cd7825ca74a4a2b43db8354825ac24fc1b7ee09e6fa3`. This verifies against the upstream HTTPS checksum, not an independently authenticated signature. Release JSON, archive, checksum and original source are retained in `source/`.

Upstream `lib/libzstd.mk:105` sets `CFLAGS ?= -O3`. The captured `logs/upstream-default-dry-run.txt` demonstrates that default. The `programs` target compiles zstd source into its executable. **The experimental O2 baseline is explicitly imposed and is neither the upstream default nor a reconstruction of installed package build flags.** Installed Pi package version 1.5.7-3 is supplied by the parent; the local builder independently reports that same package version. Installed binary recipe/flags and target libc remain unverified by this lane. A same-version stock CLI comparison is contextual, since packaging/toolchain/features can differ.

Runtime dispatch inspection: `lib/common/portability_macros.h:93–103` enables BMI2 runtime dispatch only on x86; all three captured arm64 macro dumps resolve `DYNAMIC_BMI2=0`. `compiler.h` selects ARM NEON at compile time, `compress/zstd_lazy.c` uses the little-endian NEON row path, and `decompress/zstd_decompress_block.c:1240` contains a GCC/aarch64-specific sequence-load path. These are already upstream paths, not an A72 optimization introduced here. No A72 runtime dispatcher was added. `-mtune=cortex-a72` changes scheduling while `-march=armv8-a` retains the ISA; no `-mcpu`, native ISA, crypto extension, LSE, LTO, PGO or fast-math was requested.

## Correctness and fixed corpus

`correctness.py` completed 520 successful expected-result CLI invocations in the bounded builder, with full output in `logs/correctness.txt`. For all five corpus files at levels 1/3/9: each candidate and stock compresses, every candidate/stock decoder reconstructs exact original bytes, compressed frames are byte-identical, frame checks pass, and truncated/corrupted frames are rejected. Additional checks exercise level 19, raw dictionaries decoded across every binary, and concatenated frames. This is meaningful smoke/regression coverage, not the full upstream fuzz suite. The tracked build script embeds the complete corpus generator, checks and parent runner so the procedure survives ignored artifact removal. Its outer integrated entry point was syntax-checked; the same build and correctness bodies were executed separately during this run, not redundantly rebuilt after script consolidation.

The benchmark corpus is fixed and public: uncompressed official source tar (8919040 bytes, SHA-256 `f1cb05ca79a264c240772c789429fc6ecd0d9e5fcd8be5fdeb98338841d65d2c`), 4 MiB zero bytes (`bb9f8df61474d25e71fa00722318cd387396ca1736605e1248821cc0de3d3af8`), and 4 MiB counter-hash noise (`64065bccf5575299e8a303c7da63c9aadaaa73d25b2d912584954b1b8bc451da`). Noise concatenates SHA256(`b'zstd-compiler-v1:' + i.to_bytes(8,'big')`) for `i=0..131071`. Empty and 262-byte binary inputs supplement correctness only. `corpus/manifest.json` and `corpus/SHA256SUMS` capture lengths/hashes. The source corpus is representative source text plus build metadata; zero/noise are bounds, not claims about user workloads.

## Parent-only benchmark protocol

No benchmark command in this section has been run on the Pi by this lane. Parent owns transfer, scheduling, telemetry and execution. Review `parent-benchmark.sh` in the handoff, copy it and `bin/`, `corpus/`, licenses and manifest into a private experiment directory, verify hashes, record exact installed package/binary hash and loader compatibility, then run it explicitly with Bash. Do not copy anything into system binary/library directories or change PATH globally.

Record a fresh matched v2 cohort with board revision/RAM/kernel/software versions, session/display state, governor, requested clocks, temperature, undervoltage alarms, load and memory pressure. Actual firmware clocks/throttle history and energy remain unknown unless parent supplies qualified instrumentation. Run alone on the parent-controlled board, with the same cooling and display/browser state across trials. Keep existing security, governor and memory policies. Warm caches consistently; do not drop caches. The runner uses the CLI's in-memory `-b` benchmark to reduce filesystem effects; it is not a disk, zram or package-manager benchmark.

Canned runner: eight alternating forward/reverse blocks over O2, tuned O2, O3 and stock. Each measures compression and decompression for each fixed corpus at levels 1, 3 and 9, with `--single-thread`, `-i3` and fixed CPU affinity (default CPU2, overridable with BENCH_CPU). Explicit threading matters because upstream 1.5.7 defaults to multiple workers. Logs retain complete raw CLI output per trial; stock remains a contextual reference. Temperature must be below 55°C before each trial and visible voltage alarms zero; otherwise it aborts. Parent must also monitor during trials and reject blocks with contention, alarms, pressure, frequency-policy changes or thermal drift. Cooling may require restarting the whole balanced run; an aborted partial run is not a completed comparison. Do not silently combine partial runs.

After one full run, reverse/repeat promising results under the same conditions. Report per-corpus/level compression and decompression medians, range/IQR, compressed size, and every failed/rejected block, with paired ratios against experimental O2. Compare tuned O2 against O2 to isolate scheduling; compare generic O3 against generic O2 to isolate optimization level. Stock differences do not isolate those variables. Retain negative results and size costs. Claim no Pi speed improvement until repeated matched parent results exist.
