# Physical Pi 4 Vulkan compute correctness

Parent verified target ABI, binary/shader hashes and installed loader/ICD provenance, then ran list-only followed by one bounded correctness invocation as the ordinary user. No system binary, ICD, package, device permissions, monitor, idle or security policy changed. The actual installed ICD is /usr/share/vulkan/icd.d/broadcom_icd.json; an initial guessed architecture-suffixed filename did not exist and was corrected before execution.

All three integer box-filter cases (1×1, 17×19, 257×193) matched the independent scalar reference exactly, including padding guards and unchanged input. Output contains terminal correctness=PASS; process exit zero. This demonstrates offscreen Vulkan compute for this workload on the actual V3D 4.2.14.0 / Mesa 26.2.6 driver. It does not establish desktop acceleration or hardware video decode. Raw console observations, result records, artifact/dependency hashes and sanitized health evidence are retained here. Device UUID and private invocation paths are omitted; full invocation remains in ignored local evidence.

Post-run: shell IPC responds, no compositor config errors, no failed system/user units, kernel taint zero, native voltage alarm zero, temperature 47.712°C. Exact kernel cursor review found one new firewall log and no reported GPU fault. Desktop remained locked and was not visually inspected. No firmware clocks/throttle history or energy instrumentation is available.

The scalar reference was compiled O0 for correctness. CPU reference and host submit-to-fence timings cover different work and must not be divided into a speedup. Pipeline setup, transfer/initialization, validation and kernel-worker CPU need separate accounting in a future representative performance experiment. No new tuning or application implementation is justified by this capability check alone.
