# Original-service buffer retirement subset

November 8, 2026. **NONDEPLOYABLE. Patches 0007–0010 are NOT MODULE-COMPILED.** This is a bounded ownership subset, not completion of the requested whole firmware transaction lifetime contract. Patches 0001–0009 and their evidence are immutable; only the series is appended. The final input for the parent's later combined module build is `../replayed-buffer-10/`, with the existing patched-header external Makefile. The zstd lane retains the heavy compiler lease.

## Production changes in 0010

The internal SMIO callback takes explicit immutable context, installed before waking its worker. The only production initializer caller is vc_sm_connect; the only callback consumer is the SMIO event dispatch. `callback-consumers.txt` records the complete candidate-tree search. No public dma_buf, codec or kernel-client API changes. Each of the three buffer allocation paths captures the original state before IDR publication. Late FREE, coherent mmap/free, list retirement, and event handling use that owner. Events resolve only the callback's original IDR, under its lock, then acquire the buffer mutex before retiring the entry. RELEASED requires the complete payload, a live ID and the matching nonzero firmware handle. IDs increase monotonically within a service and are never reused, including after retirement; allocation/exhaustion errors are checked before firmware publication. A duplicate or stale ID cannot become a different allocation in that service.

Last exported dma_buf release runs the actual existing vc_sm_dma_buf_release callback, sends FREE through the original service, and retains the underlying imported dma_buf, attachment and mapped scatterlist. Cleanup moved to actual resource retirement after the firmware handle is cleared by RELEASED and no client remains. The old require_released_callback=false local-success fallback is removed: queued FREE, failure, interruption, host join and service close do not clear firmware ownership. A failed FREE is logged and retains its mapping/IDR entry; there is no completed automatic retry policy yet. No synthetic acknowledgement is generated by production.

Remove first closes file/kernel admission and drains admitted calls. A separate firmware-allocation lock closes new VC_MEM_REQUEST admission, replying with the protocol's allocation failure response while continuing RELEASED delivery. It then waits for tracked buffers before stopping the owned service/worker or destroying the IDR. That wait has no timeout. This keeps the original bound device and devm storage alive through successful-buffer retirement; reprobe cannot finish ahead of that drain. The last destroy wake is paired with map_lock so remove cannot free the wait queue while the waking destructor still accesses it. A new firmware allocation racing removal either completes while the gate is held and joins the drain or receives an explicit negative allocation response.

This intentionally does not detach an arbitrary old generation into devm-free storage and does not replace the old IDR at reprobe. The state lifetime is a synchronous bound-driver drain, not a kref-based detached device lifetime. A buffer's owner pointer stays valid because the binding cannot finish removal while that buffer is tracked. Firmware silence or clients retaining buffers can therefore block explicit unbind indefinitely.

## Module and device lifetime audit

The exact-target sources already retained under `../owner-unit/` establish that DEFINE_DMA_BUF_EXPORT_INFO sets owner=THIS_MODULE; dma_buf_export obtains the exporter module ref; dma_buf_release invokes ops->release and only then module_put(owner). That pin protects the VCSM release callback through return, not later pending FREE. This subset adds no per-buffer self-reference cycle or module_put from unprotected module text. The production module_vchiq_driver exit unregisters the driver synchronously. If the final exported dma_buf ref vanishes with pending firmware ownership, module exit must enter remove and remain there through buffer drain, service retirement and SMIO worker join. Module text is not reclaimed while module exit is executing. If a RELEASED callback retires the last buffer, remove still joins the worker before returning, protecting the callback's remaining instructions. During explicit unbind, the loaded module and synchronous remove provide the same retention boundary. This reasoning requires the current successful-remove path to reach stop/join, and is not a module-loader runtime test.

No get_device-only scheme is added: get_device cannot retain devm allocations, dma_parms or a parent's binding. The original device's own remove is held open, so its devres release follows the drain. Parent transport removal/reset ordering and firmware access guarantees remain a separate live contract; retaining the child struct device alone would not establish them.

## Exact remaining live contract

**Do not deploy or claim outstanding-buffer safety for the driver as a whole.** The successful-export retirement path is now separable, but the original import/setup producers can still publish an ID before initializing the buffer mutex and ownership fields. Interrupted IMPORT can return after publication without its definitive firmware result, and current import error unwind still removes the IDR/frees/unmaps immediately, including export failure after a successful firmware import. The ioctl allocation path likewise has incomplete post-publication error/IDR cleanup. The live-buffer counter cannot repair these invalid transitions: an error may discard ownership before a delayed event. A subsequent unit must move initialization before publication, retain a transaction owner for uncertain submission, and route every successful/potentially published import and export/setup failure through definitive firmware release. It must test those actual producers and transport cancellation boundaries. No such tests pass here.

Failed FREE now preserves ownership but has no retry/recovery event; a caller must not infer that dropping the last client guarantees eventual drain. Firmware without RELEASED support likewise cannot drain this subset. A future unit must establish version readiness and a retry policy or affirmative firmware reset/drain guarantee before exposing imports. The existing protocol supplies individual RELEASED, not a demonstrated all-generation DMA reset/drain. Service stop/shutdown, worker join and timeout remain insufficient proof. Parent device unbind/reset while children drain needs a source and runtime audit. Existing successful-remove private transport/data_knl leaks, debugfs admission, firmware allocation setup/response failures, imported ERR_PTR unwind, coherent sg_table cleanup and allocation-size error handling remain unresolved. No blanket generation leak or permanent module pin is offered as the answer.

Full acceptance still needs real production import/export/setup paths, pending FREE through actual last dma_buf release, retained files and outstanding buffers across actual remove/reprobe, old-generation event delivery after that transition if the final architecture permits it, malformed/duplicate/stale IDs with all producer races, cancellation/remove races, module unload return protection, exactly-once unmap, and the parent's later combined module build plus physical qualification. Removal currently prevents a successful outstanding generation from coexisting with a completed reprobe; the source test of two contexts checks dispatch isolation only.
