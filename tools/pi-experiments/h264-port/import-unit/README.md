## Source-backed completion contract

Audit input is the exact delivered `drivers/platform/raspberrypi/vchiq-interface/vchiq_core.c`, especially `vchiq_queue_kernel_message`, `vchiq_queue_message`, `queue_message`, and `memcpy_copy_callback`; SMIO opens an ordinary service with zero/default sync, not OPENSYNC. DATA admission, service validation, quota/slot waits and copy failures return before publication of the DATA message. The kernel memcpy callback does not fail. `queue_message` fills the header, executes the visibility barriers, publishes `local->tx_pos`, signals the remote event, then returns zero; there is no subsequent failure return. Padding publication while acquiring space does not publish the IMPORT. Thus a nonzero queue return is definite nonpublication for this audited ordinary kernel-message path. Returning zero transfers uncertainty to the definitive firmware response. We do not infer firmware DMA cessation from close, shutdown, stop, worker join or a timer. This reasoning must be revisited if transport publication semantics or service sync mode change.

Before this patch, the send function returned EINTR while its command remained queued/published; producer unwind then unmapped the firmware's possible DMA target. Now IMPORT requires an internal completion hook and waits uninterruptibly once admitted. SMIO retains the command, instance and response matching; caller admission retains the generation and mapped buffer. Queue rejection returns an error safely; a valid exact-size response supplies either an explicit zero-handle rejection or the definitive handle. A malformed/truncated/oversized matching response leaves the transaction pending. Duplicate and late responses cannot alias a new request because transaction IDs never wrap; exhaustion fails before enqueue. The completion hook runs before caller completion and subsequent SMIO event dispatch, outside the transport admission lock to avoid nesting it over buffer/IDR locks. Stop, whose existing external precondition excludes new senders, waits for pending IMPORTs while their service is still alive before initiating host teardown. `complete_all` supports both the caller and stop waiter.

**Cancellation and peer-silence limit:** once admitted, even a signalled or killed caller cannot finish cancellation until the definitive IMPORT response/nonpublication result. A silent peer, only malformed replies, a lost response, or firmware without a usable RELEASED can block that call, explicit unbind, module removal and parent teardown indefinitely. There is no deadline, forced host cleanup, or invented firmware reset acknowledgement. This is a blocking contract, not a usable bounded cancellation facility. A real protocol cancellation/reset-and-DMA-drain guarantee is still required for bounded recovery. The patch must not be deployed on the strength of this host evidence.

## Actual producer ownership

Buffer locks and attachment lists are initialized in the common initializer before ID publication. The imported producer transfers its real dma_buf reference, attachment, mapping, size, address, caller ownership and setup retention to the buffer before publishing its ID. Coherent allocation likewise has its size and producer ownership initialized before export/publication. The completion hook records the firmware handle under the original generation's locks. Neither caller overwrites it after wakeup. A valid RELEASED arriving after the response but before caller return therefore remains retired. A RELEASED preceding the response is retained as an untrusted candidate handle and can retire the ID only when the definitive IMPORT handle matches it; the producer still retains storage. Conflicting early events can replace that candidate: if no matching later RELEASED arrives, retirement can remain blocked, never guessed from the conflicting event. This is an explicit remaining liveness condition, not authority to unmap uncertain ownership.

On definite nonpublication or firmware rejection, producer error cleanup removes the local ID and retires locally. On successful mapping followed by dma_buf export failure, the imported producer sends FREE through its original service and retains the ID, mapped attachment, underlying dma_buf reference, state/device and live-buffer count until actual RELEASED. Coherent sg-table/fd setup failure routes through ordinary dma_buf release with the same retention. Invalid ERR_PTR acquisitions are excluded from unmap/detach/put, fd failure returns its real error, and coherent sg-table ownership is released at final resource retirement. This fixes both identified producer holes in the source, subject to the unbounded completion contract above.

A separate setup flag protects the producer through the fd-install boundary: another thread may close an installed fd before the ioctl finishes. The real dma_buf release callback can drop client ownership and request FREE, but cannot destroy storage while setup still uses it. Producer finish clears that flag under the buffer lock and performs final retirement if no client or firmware remains. Error exits clear setup before their final local/ordinary release. IDR operations follow IDR-then-buffer locking; cleanup never removes a possibly owned firmware mapping merely because setup failed.

## Module/device retention and remaining acceptance

The synchronous admission/removal architecture from 0009/0010 is retained. The admitted import retains source state/devm storage during blocking completion; every error buffer awaiting RELEASED remains in the live-buffer drain. Remove cannot stop the event service or release child devres before that drain. The exact-target dma_buf module pin protects exported ops through release return; pending cleanup after that return remains protected by synchronous module exit/remove through live-buffer drain and worker join. Failed-export buffers have the admitted caller's protection, followed by that same driver removal boundary. No permanent module self-pin, callback-local module_put or get_device-only substitute was added. Kernel client API, userspace API, ordinary VCHIQ and dma_buf architecture remain unchanged; the internal SMIO import helper gains a mandatory completion hook.

Still open: asynchronous FREE queue failure has no confirmed retry/recovery policy; a successful enqueue is not RELEASED. A dead peer, unsupported RELEASED or externally disrupted parent transport can prevent any safe completed drain. Connected-init allocation failure paths, firmware VC_MEM_REQUEST response failures, successful-remove private transport/data_knl leaks, debugfs admission and unrelated allocation validation are not qualified here. Parent transport unbind/reset ordering still needs a real source/runtime contract. No all-generation DMA quiescence guarantee has been found. Full combined module build/modpost and real firmware/kernel dma_buf/remove/reprobe/unload acceptance remain required; old 0006 builds validate none of 0007 onward.
