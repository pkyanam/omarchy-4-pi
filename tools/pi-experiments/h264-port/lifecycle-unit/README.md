# Callback cancellation prerequisite; VCSM lifecycle remains blocked

November 8, 2026. This unit does **not** complete the requested VCSM lifecycle implementation. It implements the transport cancellation prerequisite only. The four modules compile; they remain nondeployable. No Pi, SSH, GPU, install, package recipe, staging, commit, external message or subagent was used.

## Implemented contract

`patches/0004-vchiq-synchronous-callback-cancellation.patch` is separate from the unchanged first three patches. `vchiq_remove_connected_callback()` uses upstream's existing `connected_mutex`, which is held throughout both immediate and deferred callbacks. Removal deletes a pending registration or waits for its active callback to finish. A NULL check cannot provide this guarantee. The callback must not reenter registration/cancellation or wait on a cancelling caller. Consumers must serialize re-registration against removal and retain device/state/module text through cancellation. This bounds callback lifetime, not firmware response latency; cancellation may wait indefinitely for a stuck callback.

The additive `vchiq_add_connected_callback_sync()` returns registration capacity/duplicate errors. The existing exported void registration ABI remains available and reports errors. VCSM continues using its existing registration behavior; its remove now cancels/drains connected initialization before touching state. Error-return adoption is deliberately deferred with state/error-path ownership: returning a probe failure without fixing the global state would introduce a dangling global after devm cleanup. No readiness/teardown safety beyond connected callback cancellation is claimed.

Audit `callback-users-audit-all.txt` searched every C/header in the exact target archive, plus candidate C files. There are no in-tree callers in that archive; the candidate VCSM caller is the only actual added consumer. The legacy ABI is retained for possible external consumers; no assertion that audio currently uses it is intended. Upstream callback architecture, transport header placement and dispatch locking are retained.

## Exact remaining races and required design

Source references below are in `replayed-lifecycle-03/drivers/platform/raspberrypi/vc-sm-cma/`.

1. **SMIO use-after-free on service stop:** `vc_sm_cma_vchi.c:188` has an unconditional outer loop, sleeping on `io_cmplt` at line 193, and dereferencing instance/service state after waking. `vc_sm_cma_vchi_stop()` at line 375 closes services and frees that instance at line 398 without stopping/joining the worker. In parallel, `vc_sm_cma_vchi_send_msg()` waits on a command embedded in the instance's pool at line 446. Stop can free both worker state and a waiting caller's command. Merely adding `kthread_stop()` will hang: the worker neither checks `kthread_should_stop()` nor exits its completion wait for stop. A real stop protocol must close admission, publish shutdown status, wake blocked command-pool allocators and reply waiters, make the worker observe stop, serialize/join it with transport callback closure, and defer instance freeing until all command users release ownership. Kernel thread creation also incorrectly checks NULL instead of `IS_ERR`, and the instance allocation is unchecked.
2. **Outstanding imports/free completions:** `vc_sm.c:270–283` sends FREE and retains mappings pending firmware RELEASED; `vc_sm.c:976–1002` resolves the release via the global IDR and buffer. Remove destroys that IDR at line 1529 and devm frees the state, while exported dma-bufs can retain their release callbacks. Those callbacks access the global state in `vc_sm_release_resource()` (lines 326–333) and other paths. A release after remove can use freed state; a reprobe can instead route an old buffer/reply into the new state/IDR. Unmapping DMA immediately to make remove finish can expose memory still owned by firmware. Transport close alone is not evidence that firmware has stopped accessing that mapping.
3. **Failed connect and readiness:** `vc_sm.c:1408–1425` returns on connect/service-open failure without balancing the initialized VCHIQ instance. The initialization error cleanup at line 1475 enters the unsafe stop above. `sm_inited` is set at line 1467 but never cleared; global `sm_state` survives remove as a dangling pointer. `vc_sm_cma_import_dmabuf()` at line 1582 checks state presence rather than published initialized readiness, permitting access to missing `data_knl`/service. No failed-connect or full VCSM reprobe test passed in this unit.

The next coherent implementation must give each buffer, open-file tracker, firmware transaction and service callback an immutable reference to its owning state/instance, hold device/module ownership for their full lifetimes, and replace global lookups with that context. Publish readiness only after every prerequisite succeeds; close operation admission atomically before teardown, without holding a gate across callbacks that must complete those operations. Drain or explicitly fail command owners before freeing the service. Retain firmware-owned buffers until a genuine RELEASED/quiescence guarantee exists; timeout does not prove DMA cessation. Reprobe must create a new generation and cannot reuse an old generation's IDs/state. The exact upstream service-close callback synchronization must be included in that design review.

Required subsequent tests must execute these actual VCSM C paths with injectable transport failures and controlled worker/release interleavings: failed connect/open/thread creation, actual remove/reprobe, blocked imports during shutdown, and delayed RELEASED after the last dma-buf reference. None of the transport tests above substitute for these tests. This report identifies source-level races; it invents no runtime reproduction, safe teardown result or firmware quiescence proof.
