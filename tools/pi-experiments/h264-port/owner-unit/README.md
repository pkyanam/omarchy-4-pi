## Implemented subset

`0009-vcsm-file-admission-and-balanced-connect.patch` changes only production `vc_sm.c`. A separately allocated `vc_sm_generation` owns a kref and readiness flag. The bound state owns its initial reference; each successfully opened misc file owns one reference until release. This object contains **no device, transport, buffer or devm pointers**. It is an immutable file admission identity, not the requested completed buffer-generation owner. The main state is still devm allocated.

Misc open uses the actual miscdevice placed in file->private_data by misc core, rather than selecting the current global device. Admission locks around the ready check and file-reference acquisition. File ioctl and kernel new-import hold the same mutex throughout the admitted operation, including raw SMIO handle acquisition and use. Connected init publishes ready only after service, misc node and kernel tracker initialization. Remove synchronously cancels connected initialization, takes the mutex to drain admitted calls and close readiness, releases it before misc_deregister to respect misc_mtx -> admission ordering, then performs the existing host teardown. Old files retain only the retired admission object and return ENODEV after remove/reprobe. Release no longer needs a global device. Admission may block behind a peer-dependent synchronous call indefinitely; no timeout/free shortcut is introduced. This gate does not cover asynchronous buffer callbacks or firmware requests.

`vc_sm_connect()` balances a successfully initialized private VCHIQ instance on failed connect or failed SMIO init. Failed SMIO init returns only after 0006/0007 owned-service removal has drained any partial service references. Legacy shutdown is therefore used here only for a service-free instance, not as a general service or DMA drain. Misc-registration and kernel-tracker failure unwind now stop the initialized SMIO owner before transport shutdown. Error-returning connected registration is checked and releases its generation reference on failure. The unchanged successful-remove transport and data_knl leaks are still outstanding; this unit does not claim to fix them.

## Exact remaining buffer/device/module contract

The source still routes buffer/firmware operations through global sm_state, destroys the IDR during remove, and loses devm allocations on unbind. Old buffers can therefore dereference NULL or a later generation. No freeing of old state on remove is presented as safe. Closing file admission fixes one independently testable acquisition boundary; it does not authorize outstanding-buffer remove or deployability.

Required next owner must contain the original state, device/DMA context, IDR and transport; each buffer needs an actual state ref before IDR publication, and each admitted transaction needs ownership through definitive completion. RELEASED lookup must use immutable instance userdata and safely acquire/retire that original buffer reference under the IDR lock. File admission refs in this patch cannot substitute for any of those refs. The SMIO context API and event callback are unchanged here.

Current dma-buf release calls vc_sm_clean_up_dmabuf immediately after sending FREE, before RELEASED. That prematurely unmaps the imported DMA attachment. Cleanup must move behind actual firmware release or a proven firmware reset/drain guarantee, retaining the imported dma_buf, attachment, DMA mapping and original owner until then. An interrupted IMPORT can have been published even when its caller receives EINTR; current error paths remove the IDR and free/unmap before the eventual response. A complete unit must distinguish definite nonpublication/rejection from uncertain or successful publication and preserve the mapping/transaction in the latter cases. Removing the last exported dma-buf reference must transfer ownership to that transaction, rather than losing the final module/state pin. The existing require_released_callback=false fallback assumes FREE completion without an affirmative firmware cessation guarantee; a queued FREE alone is insufficient. These paths make a small refcount-only buffer patch incoherent.

Exact-target source audit (copied offline from the SHA-pinned Linux 7.3 archive into `dma-buf.c`, `dma-buf.h`, `misc.c`, with line references in `dmabuf-owner-audit.txt`): DEFINE_DMA_BUF_EXPORT_INFO sets owner=THIS_MODULE; dma_buf_export uses try_module_get(owner); final dma_buf_release calls ops->release and then module_put(owner). Thus exporter module protection covers entry/return of the synchronous release callback only, not later firmware work retained by that callback. The misc fops owner already pins this patch's file open/ioctl/release text. A per-buffer pin dropped from the final asynchronous callback can still expose that callback's return path to unload; a service/worker owner and a synchronous drain before module-exit must retain text through callback return and worker join. A permanent self-pin at probe would prevent normal module unload and is not implemented as a solution. Likewise get_device alone retains the device object, not devm state/dma_parms or a parent's bound transport. Explicit allocations and unbind/drain ordering are required.

Host service retirement, timeout, shutdown and SMIO worker join cannot prove firmware DMA cessation. A complete remove must keep transport/event delivery and all original mappings alive until every published mapping has actual RELEASED and every uncertain IMPORT is resolved, with new firmware allocations excluded, or obtain an explicit firmware reset/drain acknowledgement guaranteeing no future access. The current protocol source supplies individual RELEASED events but no demonstrated all-generation drain/reset guarantee. Silent firmware may therefore block such a drain indefinitely; freeing on timeout, closing the service first, or blanket leaking all generations is not a valid substitute. This unit deliberately does not claim that unavailable contract or add an untested buffer lifecycle model.
