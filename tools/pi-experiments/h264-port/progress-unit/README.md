## Correction to the handoff

The OPENING branch of `vchiq_close_service_internal()` passes `service` to `queue_message()` when sending CLOSE. Near its end, the actual queue function publishes the message/tx_pos, then sets that service to CLOSESENT before unlocking/signalling the peer. Reading the close function in isolation misses this state transition. A successful initial REMOVE therefore does not leave OPENING. A late normal or sync OPENACK is ignored in CLOSESENT; the peer's CLOSE reaches `close_service_complete()` and retires the client. If sending CLOSE fails before publication, the actual REMOVE poll requeues on the nonzero close return. If rejection arrives before removal, CLOSEWAIT remains until the initial REMOVE poll frees it. If OPENACK arrives first, OPEN/OPENSYNC follows normal close. Tests below execute each ordering.

Consequently the claimed responsive-peer OPENING -> consumed REMOVE -> CLOSEWAIT-without-progress sequence is not reproduced by the actual production queue/parser/close bodies. Adding persistent synchronized intent and requeues based on the earlier boundary stub would treat its missing state mutation as a driver defect. The rejected draft (including intent spinlock and sync handler changes) is preserved in `rejected-requeue-draft/`; `rejected-requeue-edit.py` is historical, **do not run it against final source**. It is excluded from the patch series. This is a bounded correction, not a proof of all possible firmware/kernel interleavings. Actual kernel scheduler/RCU/firmware execution remains untested.

## Separable 0007

`0007-vchiq-balance-unsent-owned-open.patch` fixes a different actual defect found during this audit. `vchiq_open_service_internal()` acquires a service use before queueing OPEN, but previously returned on queue failure without releasing it. Moreover, for an owned service whose OPEN never reached the wire, 0006 unwind queued CLOSE and waited for a reply from a peer service that might never have existed. All error returns from `queue_message()` applicable to OPEN precede message/tx_pos publication; the non-DATA memcpy payload path cannot return an error after publication.

On OPEN enqueue failure 0007 releases the acquired use. For opt-in owned services only, it marks CLOSED before returning to the serialized owner, so the existing normal REMOVE poll retires locally and the existing owner reference drain completes. This does not directly free a service or infer quiescence from a timeout/EINVAL: no OPEN was published, and the unchanged poll/free/reference path still owns retirement and final release. Legacy services get the use-balance correction but retain their previous state behavior. Interrupted ACK waits still release their use; rejected ACK waits still release theirs; successful OPEN holds its use until normal close drains it. Owned API serialization and transport-alive requirements of 0006 remain mandatory. No module compile validates the new source yet.
