# SMIO command ownership and successful-close stop unit

November 8, 2026. **NONDEPLOYABLE. Full VCSM lifecycle is still incomplete.** Patch 0005 is a bounded command-lifetime and worker-stop implementation; it is not a safe remove/reprobe implementation. Patches 0001–0004, all prior logs, source trees and manifests are unchanged. `prior-manifest-check.json` checks every entry of the prior lifecycle manifest: only `patches/series` differs, by appending 0005.

## Implemented production behavior

`patches/0005-vcsm-smio-command-ownership-and-worker-stop.patch` changes only `vc_sm_cma_vchi.c`. Final source is in `replayed-smio-02/`. `export.py` compares the immutable 0004 replay with the edited `replayed-smio-01/`; `edit.py` is the retained initial draft generator, not the final exporter or replay command.

Commands now have explicit caller, queued-list and transient worker references. An interrupted synchronous caller relinquishes its reference without recycling bytes still being sent; the reply or successful stop retires the queued reference. Queue failures carry their actual error to synchronous callers instead of copying an outgoing request as a successful response. Reply matching, copying, unlinking and completion run under one mutex. Dynamic allocation replaces the embedded pool and its uncancellable semaphore wait; memory scales with outstanding transactions, and no throughput or memory-efficiency claim is made. Instance references keep admitted senders alive through cancellation and result collection.

Stop publishes `stopping` under the admission mutex, rejecting both first admission and enqueue after allocation. It wakes SMIO, closes the service while the transport instance remains alive, and calls `kthread_stop()` on the actual worker. The worker checks stopping/stop requests, including immediately after the completion wait. Close marks the service closing and wakes transport queue waiters. Once close succeeds and the worker has joined, stop completes both command lists with `-ESHUTDOWN`, retires queued references and releases the owner's instance reference. It does not free every resource speculatively or merely NULL-guard it. The borrowed transport must outlive successful stop; only the outer owner can call `vchiq_shutdown()` afterward. A stop error preserves the handle and instance ownership rather than freeing live callback state. Multiple service handles are kept unchanged until the worker joins; a separate mask tracks successfully closed services.

The owner must serialize stop and exclude fresh raw-handle acquisitions before entering stop. Internal references protect admitted calls, not an unprotected caller that acquires a pointer after its owner has freed it. **The current VCSM caller does not implement that external admission contract.** Allocation failure and `ERR_PTR` thread-creation detection are corrected, but the existing service-initialization unwind is not made lifecycle-safe.

## Unresolved lifecycle and ownership design

The following are blockers, not acceptable production limitations to waive:

1. **Real interrupted close is not the injected retry case.** Exact upstream `vchiq_core.c:3367–3422` makes close interruptible and returns `-EAGAIN` before service removal finishes. Removal may finish before retry, making the handle invalid and subsequent close return `-EINVAL`. Patch 0005 preserves state on error, but cannot distinguish that completed removal from an unsafe failed close. Its current VCSM callers ignore stop errors and proceed to destroy owner state. The init error unwind also ignores close errors and frees callback userdata. These paths remain unsafe. An owner-visible close/removal completion with callback exclusion, valid even after handle retirement, or an appropriate upstream synchronous service-removal primitive is needed; blind retries or treating every `-EINVAL` as quiescence are incorrect. No blanket leaking is presented as a fix.
2. **Transport shutdown frees memory.** `vchiq_arm.c:438–457` calls shutdown_internal then `kfree(instance)`. It cannot precede worker join. `vchiq_shutdown_internal()` ignores `vchiq_remove_service()` errors; that removal also waits interruptibly. Therefore shutdown alone does not establish userdata/callback quiescence. The outer owner must handle failed connect with no services separately from initialized-service teardown and obtain a real service-removal completion before releasing callback state. This patch intentionally does not add unsafe shutdown calls to VCSM.
3. **Immutable buffer ownership remains to implement.** Each exported/imported dma-buf, file tracker and outstanding firmware transaction must own a reference to its original VCSM generation, its device/DMA mapping and required module text. Firmware RELEASED must resolve through that same immutable instance context, never global `sm_state` or a later generation's IDR. Dropping the last dma-buf reference transfers ownership to the firmware-free transaction until RELEASED retires it. Reject FREE after admission closure cannot justify dropping that ownership. Worker join only excludes host event execution; service close is not proof firmware stopped DMA. Buffers with no RELEASED/quiescence guarantee require an explicit firmware reset/drain protocol before unmapping, not a timeout or blanket leak. Current globals, IDR destruction and devm allocation still violate this contract, so outstanding dma-buf remove/reprobe is unsafe.
4. **MMAL consumer review:** `vchiq-mmal/mmal-vchiq.c:1747–1766` lazily imports on first submission and retains `vcsm_handle`/`vc_handle`; `mmal_vchi_buffer_cleanup():1796–1811` frees that handle later. A buffer/context can therefore outlive VCSM removal. On the zero-VC-handle error branch, the code frees `vcsm_handle` without clearing it and returns the earlier zero `ret`, allowing stale-handle cleanup/double release and apparent successful submission. Fix that separately alongside real per-generation references and MMAL port/buffer teardown synchronization; changing its return code alone does not solve ownership. Codec/vb2 DMA ownership also needs the same review.
5. **Readiness and probe failures:** `vc_sm_connected_init()` still leaks the initialized transport on failed connect/open, publishes through global state, and remove does not clear global readiness. Production failed-connect, actual remove/reprobe and delayed RELEASED tests are still required. None is claimed to pass here.

The completed bounded unit is command ownership plus stop after confirmed successful service close, under external raw-handle exclusion. The full lifecycle goal remains incomplete and nondeployable.
